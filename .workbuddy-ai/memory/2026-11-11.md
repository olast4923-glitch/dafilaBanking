Domain rules: Customer has 1..* Accounts; Account is abstract. SavingsAccount = 0.05% monthly interest, deposits only, NO withdrawals. InvestmentAccount = 5% monthly interest, deposits + withdrawals, min opening BWP 500. ChequeAccount = salary, deposits + withdrawals, requires employer name/address + employed customer. Design must show interfaces, polymorphism, abstraction, inheritance, overriding, overloading.

User's constraints: must run in GitHub Codespaces as a web page AND in IntelliJ; database from Supabase.

Proposed technical approach (pending user confirmation): single Maven Java project, shared core model + controllers, two boundary layers (JavaFX desktop for IntelliJ + browser web UI on port 8080 for Codespaces), DAO interfaces behind JDBC with Supabase PostgreSQL (session pooler, env-driven credentials) as primary and H2 in-memory fallback so the marker can run it offline. BigDecimal/BWP for money. Flag: assignment says JavaFX for GUI, "H2/SQLite" or "MySQL/Oracle" for DB — Postgres is a deviation worth clearing with the lecturer.

## Layout reorganisation (user: "the interface is not proper, make it organised")

Root cause found with playwright-cli at 760px: `@media (max-width: 860px)` turned `.sidebar` into a horizontal row but left the base `height:100vh; position:sticky` untouched, so the sidebar became a full-viewport navy block and the whole app was pushed off-screen. Fixed by resetting `height:auto; align-self:auto; position:sticky; top:0; z-index:30` in that breakpoint and keeping nav labels visible (they were hidden). Also: compact `.txn-table` at ≤1000px (min-width 0, 10px padding, wrapping descriptions) so all six columns including BALANCE fit; `.table-scroll` wrappers around both tables in `index.html`; a `<560px` breakpoint (1-col quick actions/account cards, hide table ACCOUNT column); restructured `.demo-box` into labelled Email/Password rows + button; added a "Quick actions" section heading for consistent hierarchy; toast given `pointer-events:none`.

`DashboardView.java` rewritten from one long vertical stack into an organised desktop layout: `BorderPane` with brand bar, a 190px `nav-rail` (Overview / Accounts / Move money / Open account / Interest / Statements), a `StackPane` view host inside a `ScrollPane`, and a persistent bottom status bar. Each view has its own nodes (accountList + detailGrid, actionAccount combo, historyAccount combo, openAccount form, interest panel, statement text area). `setView()` toggles `visible`/`managed` and the active nav style. Added matching CSS to `fx/bank.css` (`.nav-rail`, `.nav-button`, `.nav-button-active`, `.quick-grid`, `.form-grid-2`, `.detail-grid`, `.summary-row`, `.info-card`, `.app-status`).
